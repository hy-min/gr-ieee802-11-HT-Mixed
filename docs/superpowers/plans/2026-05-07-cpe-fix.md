**Goal:** 修复 estimate_header_cpe_rad() 函数的 CPE 估计错误，恢复 L-SIG/HT-SIG 解码

**Architecture:** 问题根因是使用了错误的 pilot 参考值（复数 kLltfPilotTX 而不是实数 ±1）。修复方法：回退到使用 kHeaderPilotBase。

**Tech Stack:** GNU Radio, C++, IEEE 802.11-2016

---

## 当前状态

### Bug 描述

`estimate_header_cpe_rad()` 函数中的 CPE 估计使用了错误的 pilot 参考值：

```cpp
// 当前错误代码:
const gr_complex expect = kLltfPilotTX[i];  // 复数值
acc += eqp * std::conj(expect);

// 应该使用:
const float pilot_val = (float)kHeaderPilotBase[i];  // ±1 实数值
acc += eqp * pilot_val;
```

### 影响

- CPE 估计值始终为 0（因为复数共轭相乘后累加总是实数）
- L-SIG parity check 失败
- HT-SIG 无法解码
- HT-DATA 无法到达

## 关键代码参考

### 正确的 estimate_header_cpe_rad 实现应该是:

```cpp
static float estimate_header_cpe_rad(const gr_complex* rx52,
                                     const gr_complex* H52)
{
    gr_complex acc(0.0f, 0.0f);

    // L-SIG and HT-SIG pilots at indices 48,49,50,51
    // IEEE 802.11 defines these as real ±1 values: {1, 1, 1, -1}
    for (int i = 0; i < 4; i++) {
        const gr_complex eqp = safe_div(rx52[48 + i], H52[48 + i]);
        const float pilot_val = (float)kHeaderPilotBase[i];  // ±1 实数
        acc += eqp * pilot_val;
    }

    if (std::abs(acc) < 1e-9f) {
        return 0.0f;
    }

    return std::arg(acc);
}
```

### kHeaderPilotBase 定义位置（需确认）:

```cpp
static constexpr int kHeaderPilotBase[4] = { 1, 1, 1, -1 };
```

如果 kHeaderPilotBase 不存在，可以使用内联值：
```cpp
const float pilot_val = (i == 3) ? -1.0f : 1.0f;  // {-21} 是 -1，其他是 +1
```
