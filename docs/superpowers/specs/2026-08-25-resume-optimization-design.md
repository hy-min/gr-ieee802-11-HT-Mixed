### 项目经历 · WiFi 条目

> **开源 WiFi 接收系统代际升级与实时化攻关（C++ 数据流框架二次开发）**
> 2025.10 – 至今
> 独立项目 · 技术栈：C++ · Python · GNU Radio · Linux · git · cmake · gdb · AddressSanitizer
>
> 以 GNU Radio 社区开源 802.11a/g/p 参考收发机为起点，独立完成 802.11n HT 代际升级与
> USRP X310 平台实时化，5.25 GHz 电缆直连配置端到端 FCS 校验通过率 99.55%（2990/2983 ×2 轮、
> 无噪声风暴轮复现）。
>
> 986 次提交（2025-10 起）· C++ 净增约 1.9 万行 · Python 测试与工具代码 4 万余行 ·
> 146 份书面实验结论（截至 2026-08）
>
> - 代际升级：独立开发 5 个 C++ 模块，补全 802.11n HT 收发路径（HT-SIG 信令、TX 训练字段插入、
>   RX 符号分流、LLR 软解映射、QC-LDPC 编译码——其中 LDPC 端到端 ABAB 判定无显著增益，
>   保留为 opt-in 特性），完成 GRC 块定义、Python 绑定与流程图的全链路集成。
> - 核心链路改造：重写帧检测器为周期自相关 + 自适应门限算法，有效帧检出率提升 3.4 倍
>   （均值约 200 帧/45 秒）；重构信道估计为双训练符号 SNR 加权，HT-SIG 输入 SNR 提升 6 dB
>   （2-3 → 8.78 dB）；累计改造均衡器、MAC 解码、Viterbi 等 14 个既有模块。
> - 性能优化：逐层二分定位数据流调度器 stall（空闲 TX 路径模块等待元数据、经缓冲区背压冻结
>   全图），重构数据通路后实时吞吐由 0.035 MHz 恢复至 200+ MHz，端到端实时业务首次跑通。
> - 并发调试：使用 AddressSanitizer 定位多线程共享 static 缓冲区导致的数据竞争（gdb 下
>   不可复现的 Heisenbug），修复后满负载 45 秒持续零崩溃。
> - 解码层优化：数据路径 |H|² 加权软判决 Viterbi（N=8 配对 ABAB 终败 −62%，p=0.0047；
>   300s 长验证 −83%）与 L-SIG 多旋转候选搜索，电缆配置端到端 FCS 通过率 99.35%（3 轮）→
>   99.55%（2 轮，约 3000 帧/300 秒）。
> - 测试基建：设计 feature-flag 实验体系与统计化基准平台（N 次重复、均值 ± 方差判定、
>   一键回归门），建设 100 个测试文件与 91 个实验脚本，支撑 150 余轮受控 A/B 实验；
>   残余误码经对照实验归因于射频本振随机相位噪声的硬件物理极限（帧内无结构，不可校准）。
