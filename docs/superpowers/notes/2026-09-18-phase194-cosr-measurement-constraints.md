# Phase 194: Co-SR 测量的平台约束 —— 帧率墙与相位抽签（2026-09-18）

**类型：可行性调查（表征）+ 三次框架更正**

**起点**：用户要的是"两个设备在不同功率下，各自 FCS 成功率随**对方**功率变化的曲线"。
本 phase 调查"能否把占空比提到两帧真正相遇的量级"——**结论：不能，且原因有两个**。

## 一、接收链的帧率墙（未解）

### 事实

```
len1000 / 100ms  (10 帧/秒)  →  FCS_OK 77.1%   ✓
len1000 /  10ms  (100 帧/秒) →  FCS_OK  0.0%   ✗
len38   /   2ms  (500 帧/秒) →  FCS_OK  0.0%   ✗
len38   /   1ms  (1000 帧/秒)→  harness 信号生成撑不住，超时挂死
```

### 关键证据：接收机只处理 ~10 帧/秒，与供给无关

| 计数器 | 100ms 可用 | 10ms 失败 | 比值 |
|---|---|---|---|
| `TX_LSIG_Original`（TX 发帧）| 1,900 | 18,883 | **9.9×** |
| `HT_HEADER_TAGGED`（**TX 侧**生成）| 14,250 | 142,072 | 10.0× |
| **`LSIG_EQ`（RX 侧解 L-SIG）** | **12,256** | **10,289** | **0.84×** |
| `SPLITTER_FFT` | 1,619,747 | 563,500 | 0.35× |
| `EQ_EMIT` | 265,701 | 52,785 | 0.20× |

**帧数涨 10 倍，接收机处理的 L-SIG 几乎不变（12,256 → 10,289）。**
两臂时长相同（5×15s 窗），`.err` 体积 686MB vs 264MB（**失败臂工作量反而少**）。

### 排除

- **不是帧长**：`len38/2ms` 同样 0% ⇒ 与 `kMaxFrameRel` 那类长度问题无关
- **不是采样级过载**：无任何 UHD overflow/underflow 日志
- **TX 侧正常**：发满 9,471 帧
- **不是 harness 挂死**（除 1ms 档）：2ms/10ms 都跑满 5 窗

### 机制：**未找到**

候选（均未验证）：不应期／状态机（P157 refractory 模型）、splitter 帧间空转
（`SPLITTER_LOOP`/`SPLITTER_FFT` 之比 1.54 → 2.38）、某个 ~100ms/帧 的固定延时。

**⚠️ 唯一现成的吞吐尺已失效**：`p146_rx_throughput_probe.py`（P146，2026-07-15）
在 20k 样本上就跑不完（无 `DONE` 行，只处理到 241 个 FFT 窗即停）——
**流图不终止**，被后续改动破坏。要继续查**需先造新仪器**。

### 为什么它重要

**它阻塞了提高 Co-SR 占空比的一切手段**：

| 手段 | 结果 |
|---|---|
| 缩短周期 1ms | harness 挂死 |
| 缩短周期 2ms / 10ms | 接收链 0% |
| 加长帧 + 长周期 | ✓ 可用，但占空比仅 1.3%（len1000/100ms）|

**⇒ 当前可工作的最高占空比 ≈ 1.3–2.0%**（len1000–1500 @ 100ms）。
比 P186 的 0.1% 高 13–20 倍，但仍远不足以让碰撞频繁发生。

## 二、相对相位 φ 与"可通约周期抽签"

### φ 是什么

两条链路的帧在时间轴上的相对错位——A 的帧起点到 B 的帧起点的时间差，
由两箱各自何时启动决定，**本质上是任意的**。

两帧都长 1305µs 时，**碰撞窗 = 2×1305µs = 2.61ms = 100ms 周期的 2.61%**。

### 周期相同 ⇒ φ 冻结 ⇒ 碰撞全有或全无

**本项目全部实验都是 A/B 各 100ms（可通约）⇒ φ 是常数。**

- φ 在窗内 ⇒ **750 帧全撞**
- φ 在窗外 ⇒ **一帧不撞**

两箱时钟 ~1 ppm 漂移，75 秒只移动 ~7.5µs，**够不着 2.61ms 的窗**。

**⇒ 这解释了 P188–P191 里的臂间大幅散布**（同配置：−60.4 / −5.8 / +7.9 …）
——**它们抽到了不同的 φ**，而不只是运行间噪声。

### 修法：不可通约周期（纯软件，无需硬件）

B 的周期改成 **99ms**（而非 100ms）⇒ φ 每个 A 帧前进 1ms
⇒ **9.9 秒扫完一圈**，15 秒窗内扫 1.5 圈 ⇒ **每条臂均匀采样所有 φ，可复现**。

**代价**：平均效应 = `2.61% × 碰撞时毁伤`（低占空比下只有 ~2.6pp）。
**但可反推**：`观测均值 = (1−p)·R_clean + p·R_collided`，R_clean 单独可测
⇒ **R_collided 可解出**。

## 三、Co-SR 框架的三次更正（本 session 累积，全部是我说错的）

| # | 我说过的 | 为什么错 |
|---|---|---|
| 1 | "**高占空比**是 Co-SR 的要求" | 高占空比是**我的测量设计**的权宜，不是 Co-SR 的性质。繁忙网络里 AP 本来就可以很忙——它是*真实*工作点，但不*必需* |
| 2 | "两帧应当**对齐**" | 真实 Co-SR 里两帧本来就不对齐。对齐是测量手段，被我说成了需求 |
| 3 | "**不可通约周期**能解释 A=18 双峰" | 双峰实际是**干扰机短命**造成的。**作为解释它错了；作为控制 φ 的手段它是对的**——我用错了地方，不是想法错 |

**正确的是**：
- Co-SR 的本质 = **两个 AP 各发各的 + 协商功率 + 实现空间复用**
- 决定可行域的是 **(碰撞频率, 碰撞时的 SIR)** 两个量
- **占空比**影响前者，**功率对**影响后者，**φ 决定"这一条臂到底撞不撞"**
