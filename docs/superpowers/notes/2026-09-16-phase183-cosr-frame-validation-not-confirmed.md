## 判定

**Co-SR 帧对帧验证: NOT CONFIRMED（测量不可用）**
- 开跑前用 `p181_channel_stability.py` 验证链路健康：**mean 91.67%, sd 2.20,
  零事件**——排除了"链路本来就不稳"这一解释
- 同功率两趟，6 档中 3 档吻合（0/12/31.5）、3 档不吻合（6/18/24），
  最大差 66.4pp
- 即便只统计"B 帧确实送达"的 8 个臂，形态仍不单调：
  `6dB 29/11% → 12dB 93% → 18dB 4% → 24dB 42/18.5% → 31.5dB 70/75%`
- 分子分母窗口：分母 est_sent~150/15s 窗 ×4 窗 = 600/臂（interval 100ms，
  warmup 20s 已由 harness 排除）；分子 FCS_OK = [RESULT] per-window 计数器差值

**可确定的部分结论**（有数据支撑）：
- **高占空比帧干扰确实能摧毁受害链路**：8 个送达臂中 5 个跌到 4-29%，
  而 P179 的低占空比帧（0.12%）在 0-31.5 dB 全程无效应。占空比是必要条件。
- **受害链路存在两个可区分的状态**，由自身 churn 体积完美分离：
  `B帧到达=0 → stderr 41-49MB → 69-96%`；`B帧到达>0 → stderr 283-1342MB → 4-93%`
- **但"送达"不等于"崩溃"**：arm 10 送达 498 次、churn 376MB，仍 92.8% 健康

**不能确定的部分**（本 phase 未解决）：
- 门限功率位置
- 两个候选解释——接收机双稳 vs 干扰源波动——**当前数据无法分离**
- 状态转移的触发器（arm 6 逐窗 133/136/126/**23**：健康维持 45s 后单窗内翻转）

## 机制与实现

- 复用 `p182_ota_noise_sweep.py` 新增的 `--b-frames` 模式（B 走正常帧发射链，
  仅调 `--b-len/--b-interval` 提高占空比；**零 harness 代码改动**）
- 占空比：MCS0 / PSDU 1028B → 318 符号 → 帧长 **1.30 ms**；interval 5ms
  → **26.1%**；受害帧（0.12ms/100ms）被击中概率 ≈ **28.5%**
- **方法学修正（本 phase 发现）**：有效性检验的帧长必须跟着干扰方的 PSDU
  走。P179/P182 用的是 `len=89`（B 的 PSDU 当时是 61+28），本 phase B 改成
  len1000 后 PSDU=1028，**旧的 `len89` 恒为 0，会误判为"干扰未送达"**。
  本 phase 起用 `len=1028`
- **另一处方法学教训**：为省磁盘，脚本在每臂结束后删除 B 的日志——**代价是
  丢失了 B 自身是否/如何发射的诊断**（本 phase 无法回答"那 4 个零送达的臂
  B 有没有在发"）。后续应保留 B 的关键行或摘要
