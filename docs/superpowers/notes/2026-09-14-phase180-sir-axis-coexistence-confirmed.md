## 机制与实现

- 新脚本 `p180_sir_sweep.py`（纯编排零 C++ 改动）：A 功率档回文
  `31.5,16,8,0,0,8,16,31.5`，每档两臂（B 静默 / B 满功率）背靠背；
  **升降段臂序翻转**（升段 silent→max、降段 max→silent）控制臂序偏置
- **机制结论**：受害方自链路为同箱内两子板近场耦合，余量极大。即使受害方
  自身发射降 31.5dB（自身链路已因 SNR 不足跌到 52%），干扰方在受害接收机处
  仍远低于捕获门限——**耦合不对称性（同箱近场 vs 跨箱）主导 SIR，Tx 增益
  的可调范围不足以跨越它**
- **OTA 路径封闭**：P178 净判定给出的两条 OTA 路径——"更近箱距"（P179b 已测
  <10cm 无效应）与"调功率"（本 phase）——**均已实测封闭**。剩余唯一路径 =
  P178 另一条建议：电缆 2×2 受控 SIR 信道

### 工具教训（P181 三轮全 0% 的根因）

**stderr 管道死锁（本 phase 自造 bug，非设备故障）**：p181 初版用
`readline()` 逐行读 stdout，却把 stderr 设为 PIPE 且仅在结束时读取。harness
经 USRP_LOG 大量写 stderr（实测 **337MB/15min ≈ 375KB/s**），**写满 64KiB
管道缓冲即阻塞在 write()**，收发线程随之停摆 → 全程 0/150、进程卡在
`futex_do_wait` 不退出（被误判为"设备挂死"）。

- **诊断证据**：失败运行的 stderr 恰好 64K（= 管道缓冲上限）、进程状态
  futex_do_wait、长跑全死而短测（stderr 到不了 64K）全活
- **修复**：stderr 直接重定向到文件（`stderr=err_fh`），任何情况都不阻塞；
  另加逐窗即写盘 + 静默看门狗（`run+60s` 无输出判挂死）
- **不受影响**：p179/p179b/p180 均用 `communicate()`（并发读双管道，无死锁），
  其结果与结论不受此 bug 影响

### 工具教训 2：臂崩塌的真实机制 = splitter force-transition 循环

**原表述更正**：P179/P179b/P180 各臂偶发的「整臂崩塌」（逐窗 128/114/32/3/5
或 6/6/6/20/5）此前被写作「**环境瞬态**」/「**热瞬态**」——**均不正确**。
同日组件级调试（日志计数逐层定位）证明是**测量系统自身的瞬态**：

- **发射侧完全正常**：健康臂与崩塌臂 TX 链标签数一字不差（`TX_LSIG=2850`、
  `TX_HT_SIG=3800`、`TX_SCRAMBLER=1900`、`SIGNAL_GEN=2850`、`MAPPER=1`）
- **上游检测器误触发 42×**：`wifi_start` 标签 健康 969 → 崩塌 40673
- **机制**（`lib/ht_symbol_splitter_impl.cc:376-396`）：帧进行中收到新
  `wifi_start` → splitter 走 `force-transition` 分支**强制抛弃当前帧重启**。
  该路径健康臂 **0** 次、崩塌臂 **37995** 次（占该臂 frame-start 的 93%）。
  真帧被反复抛弃 → 永不完整 → 解码失败，而 `FCS_FAIL` 恒 0（从未走到 FCS）
  ——这正是本 phase 看到的「到达率暴跌 + FCS_FAIL=0」矛盾的解释
- **churn 状态**：崩塌臂 stderr 93.9MB vs 同档正常静默臂 27MB（3.5×）；
  `[SPLITTER_LOOP] produced=0` 空转 27 万次
- **已排除**：残留干扰进程/脏退出（崩塌臂 B帧@A=16 vs 真干扰臂 782）、
  TX 欠载（TX 标签数相同、UHD 标记恒 ~950/臂）、CPU 热节流（满频 4.4-5.4GHz）、
  信号衰落（逐帧 SNR 3-14dB 无单调趋势）
- **仍未确定**：触发该循环的条件（日志 I/O 争用为主假设，但证据不足——单流图
  长跑 P181 写 337MB 零崩塌，与短臂 I/O 速率相当）
- **实用处置（已验证有效）**：逐窗口形态判别（**单调递减** = 系统瞬态签名；
  均匀低 = 持续条件）配合配对臂对照，可识别并剔除崩塌臂。本次 16 臂中 2 个
  受影响臂均被正确剔除，**结论数字未受污染**

## 更正 2026-09-15（P182 后追加）：测量成立，「共存」解读不成立

与 P179/P179b 同源更正。本文件的测量（受害方功率 31.5→0dB 全程干扰效应
−0.02pp）仍然有效，**但「全 SIR 范围共存」的解读不成立**。

**真实原因 = 干扰的占空比**：干扰箱 B 发**帧**（帧长 ~120µs / 周期 100ms，
占空比 **0.12%**），与受害帧在时间上重叠的概率仅 **0.24%**。本 phase 的有效性
检验（每个 max 臂 B 帧在 A 处被检测 ~3537-3646 次）**只证明干扰信号到达了
受害接收机，并不证明它覆盖了受害帧**——「到达」与「重叠」是两回事，
本 phase 把它们混同了。

**「SIR」这个词在本文件里的用法也需修正**：降受害方功率确实降低了它自身的
SNR（0 dB 时 52% vs 16 dB 时 97%），但**并没有把 SIR 压进门限**——因为干扰方
在每个受害帧上的**时间覆盖率**始终是 0.24%，与功率比无关。

**P182 的对照**（同轴、同桌 B、同几何，改发连续噪声使占空比→100%）：
6→8 dB 骤降 52pp，满功率 −65pp。详见
`2026-09-14-phase182-cosr-continuous-noise-confirmed.md`。
