# Phase 192: 接收链路的长帧硬限制 —— 干净自链路下的 0%（2026-09-18）

**类型：单变量判别实验（表征）**

## 起点：一个从未被追问的事实

P188–P191 的所有干扰臂都用 B = `len1000 / 10ms`（帧长 1305µs，占空比 13.05%）。
**B 自己的链路在那六臂里全部解出 0 帧**（`DECODE_SUCCESS=0`），而同一台设备的
自链路在 `len38 / 100ms` 下是 ~75%（P186）——**没有人问过为什么。**

这件事卡在 Co-SR 的咽喉上：Co-SR 是"两个 AP 同时通信"，**双方都需要高占空比**；
若一条链路连自身的高占空比都承受不了，则两链路共存在本几何下不可能——**与干扰协调无关**。

## 主结果

| len | PSDU | 符号数 | FCS_OK |
|---|---|---|---|
| 38 | 66 | 22 | **89.3%** |
| 100 | 128 | 39 | 87.6% |
| 200 | 228 | 70 | 54.3% |
| **400** | 428 | 132 | **0.0%** |
| 700 | 728 | 224 | 0.0% |
| 1000 | 1028 | 318 | 0.0% |

**断点在 len200 与 len400 之间；len ≥ 400 完全失效。**

⚠️ **这是干净自链路、零干扰源、信噪比充足下的失败**——与 Co-SR、与任何外部干扰无关。

## 被实验逐一排除的假设

| 假设 | 检验方式 | 结果 |
|---|---|---|
| **占空比过高** | len1000 在 1.3% vs 12.7% 占空比 | ❌ 同样 0.0% |
| **累积 CFO** | 开 `HDR_COMP_DISABLE=0`（逐符号补偿）| ❌ 毫无帮助 |
| **虚假标签打断** | 查那道 >50% 防护的开火次数 | ❌ **从未开火**（0 次）；`INCOMPLETE` 仅 6–21 次 / 750 帧 |
| **符号丢失** | 分析 `syms=N/M` 的分布 | ❌ 呈 **1..M 均匀分布** ⇒ 帧跑满 |

**关于"虚假标签"的说明**：`lib/decode_mac.cc:466` 确有一道防护——
虚假 `frame_bytes` 标签只在"已拷贝 >50%"时被忽略，否则整帧作废。
我一度据此推测长帧更易被打断（暴露窗口更长）。**但实测该防护在六条臂上开火 0 次**，
推测不成立。**代码里读到的机制必须用计数验证。**

## 实际失败形态：帧完整、内容坏

| 臂 | CAPTURE 行 | **COMPLETE** | INCOMPLETE | FCS_OK |
|---|---|---|---|---|
| L38 | 19,508 | 879 | 21 | 670 |
| L100 | 35,025 | 860 | 21 | 657 |
| L200 | 50,479 | 716 | 18 | 407 |
| **L400** | 31,619 | **236** | 6 | **0** |

**L400 里 decode_mac 完整重组了 236 帧，却没有一帧通过 FCS。**

（CAPTURE 31,619 ÷ 132 符号/帧 = 240 ≈ COMPLETE 236 ✓ 自洽。）

⇒ **不是"收不全"，是"收全了但解错了"**——错误发生在头部之后的符号级处理
（均衡/解调），不在重组环节。

## 这不是配置上限

```c
// lib/utils.h:16
#define MAX_PAYLOAD_SIZE 1500
#define MAX_SYM          (((16 + 8*(1500+28) + 6)/24) + 1)   // = 511 符号
```

**设计支持到 511 符号（payload 1500），实测断点在 70–132 符号——差 4–7 倍。**
接收链**远未达到设计范围就崩了**。

**该限制此前不可见**：本项目全部实验程序（P31 至今）都用 `len38`（22 符号），
**从未测过更长的帧**。

## 对 Co-SR 的意义（本 phase 最有价值的产出）

1. **解释了 P188–P191 里 B 的六臂零解码**——不是干扰，是长帧 RX 限制
2. **给"链路占空比"封了顶**：占空比 = 帧长 × 速率，而帧长有硬上限
3. ⇒ **本平台上可构建的 Co-SR 形态被这个限制界定了**：在能可靠解码的帧长范围内
   （目前 ≤ len200），链路占空比最高只有 ~0.3%（100ms 周期），
   **远达不到"两个 AP 同时高占空比通信"的要求**

## 未解决

**根因未找到。** 已定位到"接收链、头部之后、帧完整但内容错"，
未确定是均衡器、splitter 的符号定位、还是别的环节。

**下一步（未做）**：开 `IEEE80211_SYM52_DUMP=1` 或 `IEEE80211_HTSIG_BIN_DUMP=1`
对比 len200（54% 可用）与 len400（0%）的**逐符号星座**，看错误是
从第几个符号开始、以什么形式（相位旋转 / 幅度塌陷 / 完全随机）出现。

**优先级：高。** 与 A=31.5 的崩塌不同，**这个限制直接界定 Co-SR 的可行域**。
