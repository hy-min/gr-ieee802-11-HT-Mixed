# Phase 182 verdict: Co-SR 连续噪声干扰 CONFIRMED — 占空比是决定因素，门限 6-8 dB（2026-09-14）

VERDICT: 连续噪声干扰 CONFIRMED——干扰箱 B 发射**连续带内噪声**（占空比 100%）
时，受害链路在 B tx-gain **6→8 dB 之间骤降 52pp**（两趟独立复现），
满功率段稳定在 7-12%（−78~−83pp）。对照 P179/P179b/P180：**同一根 tx-gain 轴、
同一台 B、同一几何下，B 发射帧时 0-31.5 dB 全程无效应**。

**结论：决定 Co-SR 影响的是干扰的发射时间结构（占空比），不是发射功率本身。**
机制：MCS0 帧长 ~120µs / 100ms 周期 → 占空比 0.12% → 两条独立频闪链路的帧
在时间上重叠概率仅 ~0.24%；换成连续噪声后占空比 100%，同样功率下作用于
受害帧的干扰能量提升约 29 dB。**本项目此前从未在实机上构造出"两系统同时
发射"这个 Co-SR 前提**。

## 机制与实现

**占空比机制（本 phase 核心）**
- 帧长：MCS0 / PSDU 66 → 22 数据符号 × 4µs + 前导 ~32µs ≈ **120µs**；周期 100ms
- 占空比 **0.12%**；两条**独立频闪**链路的帧重叠概率 ≈ 2×120µs/100ms = **0.24%**
- → P179 系列中干扰**几乎从不与受害帧在时间上重叠**，从未获得作用机会
- 连续噪声占空比 **100%** → 每个受害帧都被干扰；同功率下干扰能量 +29 dB
- **P178 离线之所以测出捕获效应，正因它人为把两帧按 τ=0 对齐混合**
  ——实时扫描自动产生该巧合的概率只有 0.24%

**实现（零 harness 代码改动）**
- `--tx-file` 已支持循环播放（`blocks.file_source(..., True)`，
  test_usrp_rxonly_instrumented.py:294），B 的噪声波形直连 `uhd_sink`
  （live TX hier 转向 null_sink）
- 波形：复高斯 σ=0.32，n=2,074,000 采样（1.037 s @20Msps）——
  **长度刻意不是 2e6（100ms 周期）的整数倍**，避免噪声与帧频闪锁相
- 新编排脚本 `p182_ota_noise_sweep.py`：A/B/A 交错 + 回文 + `--b-gains`/`--levels`
  两种扫描轴 + `--exclude-arms` 标记剔除 + `--replot` 离线出图
- **受害臂 stderr 直连文件**（不用管道），见下

## 测量系统不稳定（如实记录）

本 phase 观察到并部分定位了一个贯穿 P179/P179b/P180 的问题：
**偶发整臂崩塌**（受害链路从一个 ~90% 突降到 5-20%）。

**机制已代码级定位**：`lib/ht_symbol_splitter_impl.cc:376-396` 的
`force-transition` 分支——帧进行中收到新的 `wifi_start` 标签时，splitter
**强制抛弃当前帧重启**。该路径在健康臂出现 **0** 次，崩塌臂可达
**11427-37995** 次（占该臂 frame-start 的 78-93%）。真帧被反复抛弃 →
永不完整 → 解码失败，且 `FCS_FAIL` 恒 0（帧从未走到 FCS 校验）。

**已排除的触发器**：残留干扰进程/脏退出（崩塌臂 B帧@A≈0）、TX 欠载
（TX 链标签数两臂一字不差）、CPU 热节流（满频、无节流事件）、信号衰落
（逐帧 SNR 3-14dB 无单调趋势）。

**已确认的重要贡献因素**：受害臂 stderr 走**管道**时显著提高崩塌率。
单变量 A/B（同一时刻、同一参数、仅改 stderr 去向）：

```
stderr → PIPE + communicate():  静默臂 39.2%
stderr → 文件:                  静默臂 87.5%   (+48.3pp)
```

机制：harness 的 `fprintf(stderr)` 非缓冲（每行一次 `write()`），日志速率
实测 8-11 MB/s；经管道时产生每行一次父进程唤醒的调度风暴，扰动流图实时性。
`p181_channel_stability.py`（始终写文件）在同日 session 中从未崩塌一次
（93.8% / 92.5%，sd 2.6）。

**但仍非唯一触发器**：本 phase 在 stderr→文件下也观察到一次崩塌
（粗扫轮 arm 0），故触发条件**尚未完全确定**，作为已知测量风险记录。

**已投入使用的处置手段**（有效）：
- 逐窗口形态判别：**臂内单调/持续上升或下降 = 系统瞬态**（剔除）；
  **均匀低 = 持续压制**（真实效应）
- 交错 A/B/A + 回文：两端静默臂互为漂移对照（本轮漂移仅 2.9pp）
- `--exclude-arms` 显式标记剔除并记录理由

## 决策

- **Co-SR 功率协商的定量依据**：实验床上连续干扰的门限为 B tx-gain **6-8 dB**；
  低于此值干扰可忽略（≤6 dB 时受害方仍 ≥63%），高于此值即灾难性（8 dB 起 ≤16%）
- **帧干扰与噪声干扰不可互换**：任何用"发射功率"推断 Co-SR 影响的建模
  （含"干扰即噪声"假设在**突发帧**场景下的应用）在本实验床上都是错的——
  决定因素是占空比
- 无默认翻转、无新 env var、无禁止方向变更
