# Phase 83 — Pause Memo: synthetic test cannot validate LUT

**Date**: 2026-07-04
**Branch**: TEST1
**Status**: 🔴 PAUSE — Subagent-driven P80b Task 1 BLOCKED on plan design

## What happened

启动 Phase 80b Subagent-Driven 模式 (本计划 `docs/superpowers/plans/2026-07-04-htsig-per-sc-cal-post81.md`)。
派遣第一个 implementer subagent 实施 Task 1 (合成 per-SC LUT 4-test 套件)。

Subagent 报告 `BLOCKED`，发现 plan 代码存在 4 个独立 bug，均经过验证：

### Bug 1: `viterbi_decode_133_171` 签名错误
- Plan 调用：`viterbi_decode_133_171(bits, 48)` 期望返回 24 decoded bits
- 实际签名 (examples/test_htsig_viterbi_synthetic.py:275)：`viterbi_decode_133_171(rx_bits) -> (decoded, metric)`
- 影响：plan 的所有 parity-OK 检查无法运行

### Bug 2: 硬判决极性反转
- TX 符号：`tx_syms = 1j * (1 - 2*bit)` → bit=1 → imag=-1
- Plan 判决：`bits = (eq48.imag >= 0)` → 编码反向
- 验证：30 dB SNR 下 1/48 bits 匹配（vs 46/48 正确）
- 影响：所有合成测试的"成功"实际是"失败"

### Bug 3: LUT 构建忽略 QBPSK 符号模糊性
- `eq48 = tx_syms * H * bias + noise`，`arg(eq48)` 在 ±π/2 之间跳（随机 TX bits）
- 中位数在两个 ±π/2 符号之间，统计无意义
- 合成路径可除以 `tx_syms` 修复；USRP 路径（Task 7）必须用 ±π/4 网格吸附

### Bug 4: Parity 成功度量不可达
- 随机 viterbi 输出的 parity-OK 概率 ~50% (随机)
- Plan 阈值 ≥70% 在 6 dB SNR 下不可达
- 必须改为 BER-基度量

### Subagent 评估（最关键）

> "the synthetic channel model has only MAGNITUDE nulls (no per-SC PHASE noise
> beyond the bias itself). The LUT is designed to fix PHASE errors per-SC.
> **The synthetic test proves the LUT INFRASTRUCTURE works** (no regression,
> magnitudes unity, Δ-correlated) — it does NOT prove LUT helps in adversarial
> conditions. **Adversarial LUT validation must come from USRP replay (Task 8).**"

## 为什么这关系重大

即使修复 4 个 bug + 放宽阈值后合成测试 PASS，**也不能证明 LUT 在 USRP 上有效**。

LUT 设计的对手机理是 USRP 真实 RF 链路的 per-SC 相位噪声。合成通道只建模了：
- 5 个 MAGNITUDE null SCs（Phase 78b 观察）
- 单一 bias 相位

**没建模**：
- USRP UBX-160 LO 相位噪声 per-frame 残余
- IQ 不平衡 per-SC
- 64-PSK ADC 量化相位残差 (Phase 33b)
- 每 SC 的采样时钟 SFO（即使 δ 校正后仍有残余）

合成测试 PASS 能给的最高承诺是「LUT 基础设施没破」，**但这是循环论证**（合成设计的 LUT 和合成设计的通道是匹配的）。

## 与历史 REFUTED 链的一致性

| 阶段 | 合成 PASS | USRP REFUTED | 根因 |
|---|---|---|---|
| Phase 33 | 64-PSK residual 模型 | 0/90 | 真实相位噪声 ≠ 64-PSK residual |
| Phase 35 | pilot CPE 12% | 无效 | 4 pilot 不够估计 48 SC 频率选择性 |
| Phase 78a | 91% | – | 合成旋转 null ≠ USRP 稳定 null |
| **Phase 80b** | (预期) PASS | (预期) REFUTED | 合成相位 bias ≠ USRP 真实 RF 相位噪声 |

## 决策

⏸ **暂停 Subagent-Driven 流程**，把根本设计问题暴露给用户。

继续 Phase 80b 实施有两个选项：

### 选项 A：强行推进 P80b（不推荐）
- 接受 subagent 修复 + 放宽合成阈值
- 合成测试 PASS（基础设施 OK）
- 5250 USRP replay (Task 8) 极可能再次 REFUTED
- 浪费 5-7 天实施周期 = 0 dB 进展

### 选项 B：寻找"USRP-physics-meaningful 合成通道"（推荐）
- 修改合成通道模型，加入真实 RF 链路损伤的代理：
  - 真实 UBX-160 规格（LO phase noise ≈ 0.5-0.7 rad RMS @5 GHz）
  - ADC LSB-induced 64-PSK residual (Phase 33b)
  - USRP 实测 5 stable null SCs (Phase 78b)
  - 当前已知 per-SC bias 来自离线 H_hdr52 capture
- 跑 LUT-over-this-real-channel 测试，看 LUT 是否有正期望收益
- 这是 Phase 78a 风格的"matching-impaired-synthetic-test"，但用实测 H_hdr52
- 预期：如果 LUT 连这个都帮不上，USRP 也帮不上，**避免无效 P80b 实施**

### 选项 C：彻底换路线（最干净）
- 接受当前 P81 verdict："air path REFUTED + cable 5250 SNR 9.6 dB 但 rate=0x9 阻断"
- 直接回滚到 Phase 34 之前，先修复 Phase 34 在 5250 上把 L-SIG 解码 rate=0x9 的 bug（**修复 δ 校正算法本身而非绕过 RATE 检查**）
- Phase 34 真正修复后，5250 自然解锁，无需 LUT 也无需 rate-accept
- 这是诊断的反向工程：先 ROOT CAUSE，再针对性 FIX，不靠 LUT 这种"工程黑魔法"
