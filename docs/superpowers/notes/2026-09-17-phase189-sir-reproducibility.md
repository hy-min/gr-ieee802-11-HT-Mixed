## 一个未验证的机制候选（供下次）

**两台的帧周期是标称精确 10:1**（A 每 100ms、B 每 10ms），但**两箱时钟独立**，
相对相位以 ppm 级漂移（~1µs/s）：

- **单臂内**（75s）漂移仅 ~75µs ≪ B 帧长 1305µs → **同一臂内 750 个 A 帧经历几乎相同的相位**
- **跨批次**（~20 分钟）漂移 ~1.2ms ≈ B 帧长 → **相位可落入完全不同的区间**

⇒ 预测损失**双模态**：相位落在覆盖窗内 → 大损失；落在窗外 → 零损失。
实测差值确实分成两簇（近零簇 vs −30~−67pp 簇）。

**若成立，则修法不是增加重复次数，而是消除相位锁定**：
把 B 的周期改成**与 100ms 不可通约**（如 9.7ms 而非 10ms），
让相对相位在单臂内扫遍所有取值 → 每臂得到相同的相位平均。

**注意**：本候选**不能解释** A=18 的 +0.1pp（SIR +2.5 dB 已低于 +8.5 dB 的捕获守住点，
按曲线应有 >12% 毁伤）。且 −60pp 量级远超 14.25% 重叠上限，
仍需"接收机占据"机制配合解释。**未验证，不得作为结论。**

# 追加（2026-09-18）：干扰机存活缺陷 —— 两个「无效应」读数是仪表故障

## 发现

补测批次（`--tag sirpal_fill`）跑 A=18 时打出 `WARNING: interferer died mid-point`。
顺着查干扰机的发帧日志，发现 **B 的存活时长在各臂之间相差 8 倍**：

| 臂 | `TX_LSIG_Original` 行数 | ≈ 帧数 | ≈ B 存活 |
|---|---|---|---|
| 正常臂（多数）| ~25,300 | 12,650 | 126s |
| P189 idx02（A=18 asc）| **10,952** | 5,476 | **55s** |
| P189b idx01（A=18 asc）| **51,684** | 25,842 | **258s（自然退出）** |
| P189b idx02（A=31.5 desc）| **6,668** | 3,334 | **33s** |

（`TX_LSIG_Original` 每帧打印 2 次，由「正常臂 25,300 行 ≈ 125s 臂长 @100Hz」经验确定。）

## 根因

`start_interferer()` 给 B 的 `--run` 是 **240s**（+20s warmup = **260s 后自然退出**）。

- **正常臂**：受害机 ~125s 跑完，B 在 260s 前被脚本杀掉 → 无问题
- **带重试的臂**：受害机第一次尝试可能耗满 245s 超时（`timeout = warmup + run*windows + 150`），
  第二次再跑 ~125s → **总时长 ~370s** → **B 在 260s 自然退出**。
  而受害机的**测量窗口（第二个 attempt）从 ~245s 才开始** →
  **整个测量窗口里，干扰机只在前 15 秒存在。**

## 后果：虚假的「无效应」

干扰机缺席时，受害机测到的就是自己的静默基线。于是**仪表故障伪装成物理结论**：

| 测量 | 读出的差值 | B 的实际情况 | 真实判定 |
|---|---|---|---|
| P188 | −19.9pp | 正常（25,326 行）| ✅ 有效 |
| P189 asc | **+0.1pp** | 只跑了 55s / 125s 臂长 | ❌ **伪「无效应」** |
| P189 desc | −17.1pp | 正常（25,304 行）| ✅ 有效 |
| P189b fill | **−0.67pp** | 258s 自然退出，死在测量窗口前 | ❌ **伪「无效应」** |

**A=18 结案：真实效应 ≈ −18.5pp**（两个有效测量 −19.9 / −17.1），
与 A=24 的 −12.1 一起落在同一单调趋势上。

**方法论教训**：我此前给「重试」加了校验、对「瞬态」做了目视检查，
**却从未校验干扰机是否全程在场**。这个漏洞让一个虚假读数骗过了整轮分析——
而且它伪装的方向最危险：**故障产生的是「零效应」，恰好是 P179–P184 六轮得到过的那个结论，
所以它不会被当成异常，只会被当成又一次印证。**

## 修复（`p180_sir_sweep.py`，编排脚本，`lib/`/harness 零改动）

1. **B 的 `--run` 240 → 900**：B 只能被脚本显式杀死，杜绝「自然退出落在测量窗口内」
2. **新增 `interferer_lifetime_s()`**：从 B 的 TX 日志反推存活时长
3. **新增有效性门**：`valid = infra_ok and len(windows) >= windows and
   (not b_on or (not b_died and b_life >= 0.75*(grace + run*windows)))`
4. **无效臂标 `INVALID` 并丢弃**，**不再写入 0.0%**
   —— 此前 `rate_of([])` 返回 0.0，**一个完整的臂失败会伪装成「完全摧毁」**，
   与干扰机短命伪装成的「无效应」方向相反但同样是伪造

**对历史数据的验证**（门限 75s）：

```
P189  idx02  b_life= 54.8s  INVALID   <- 读 +0.1pp 的那一臂
P189b idx02  b_life= 33.3s  INVALID   <- max 臂失败的那一臂
其余 10 臂  b_life= 125.7 - 138.0s   全部 ok（无误伤）
```

**单靠 lifetime 抓不住 P189b idx01**（B 跑了 258s，够长，但死在第二个 attempt 开始前）
—— 必须配合 `b_died` 标志。两个判据互补，脚本中同时启用。

# 追加 2（2026-09-18）：ENOSPC 崩溃 —— 第三类未校验的环境假设

## 事故

重跑批次（`--tag sirpal_fix`）在 **A=31.5 desc max 臂**运行中被内核打死：

```
File "p180_sir_sweep.py", line 150, in run_victim
    (outdir / f'{tag}_attempt{attempt}.err').write_text(err or '')
OSError: [Errno 28] No space left on device
```

**根因**：根文件系统 `/dev/nvme0n1p6 → /` 被本 session 的实验数据写满
（`/tmp` 与 `/home` 同盘，所以 `/tmp` 一并失效，连 Edit 工具都无法写入）。
harness 的 stderr 每臂 50–300 MB（splitter 风暴每臂 ~260 万行），
二十多个臂累积约 16 GB。

**代价**：崩溃正在 A=31.5 desc max 臂运行中——**但事后审计（P190）发现数据其实存活**：
`run_victim` 里 `.out` 的写入在 `.err` **之前**，所以那个臂的 stdout（5 窗、79.6%、CAPTURE 840,760）
已落盘。**丢的是 `.err` 和紧随其后的 silent 臂**，不是两臂全丢（此句为本文件原文的更正）。
清理 `.err` 与干扰机日志后释放约 10 GB。

## 修复

脚本开头与**每臂之前**各加一道磁盘门（`MIN_FREE_GB = 3.0`）：

```python
if free_gb(CAP_ROOT) < MIN_FREE_GB:
    print(f'[SIR] ABORT before idx {idx} {arm}: only {free_gb(CAP_ROOT):.1f} GB free '
          f'--- stopping NOW rather than dying inside a write and losing the arm')
    aborted = True; break
```

**为什么要在每臂之前而不是只在开头**：一次崩溃会丢掉**正在跑的那一臂**，
而开头检查无法预见中途耗尽。

|---|---|---|---|
| 1 | 干扰机全程在场 | **「无效应」物理结论**（最危险）| `interferer_lifetime_s()` + `b_died` 有效性门 |
| 2 | 受害机臂会正常产出 | 整臂失败被 `rate_of([])=0.0` 记为**「完全摧毁」** | 无效臂标 `INVALID` 丢弃 |
| 3 | 磁盘空间充足 | **脚本被内核打死，数据静默丢失** | 每臂前磁盘门 `MIN_FREE_GB` |

**统一教训（本 session 最大的方法论产出）**：

> **批次脚本对环境的前置假设必须显式校验，因为违反假设的后果不会表现为
> 「脚本坏了」，而会伪装成物理结论、或静默吞掉数据。**
>
> 前两类伪装**方向恰好互补**——干扰机缺席伪装成「零效应」，
> 受害机失败伪装成「完全摧毁」——**两者都在本 session 中真实发生过并一度骗过我**。

## 动机：仪器在反复变长

## 新仪器：`[decode_mac][CAPTURE]`

该日志**逐符号组装一个帧时打一行**，所以它的计数 = **真正到达解码器的帧材料量**。
跨全部历史臂定标：

## 落地
